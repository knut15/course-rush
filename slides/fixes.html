고치는 방법 네 가지

M2  비관적 락

SELECT ... FOR UPDATE

행을 잠근다. 정확하지만 전부 줄을 선다.

M3  낙관적 락

UPDATE ... WHERE version = $1

잠그지 않는다. 충돌하면 다시 읽고 재시도.

M4  DB 원자적 갱신

UPDATE ... WHERE enrolled < capacity

판정과 확보를 한 문장이 함께 한다.

M5  Redis 선점

EVAL <lua> — DECR + SISMEMBER

판정을 DB 밖으로. DB 는 결과만 적는다.

규칙은 둘 — 정원, 그리고 중복신청 방지

중복신청 규칙 하나가 M4와 M5에 트랜잭션과 보상 로직을 불러옵니다. 정원만 있었다면 M4는 UPDATE 한 문장으로 끝났습니다. 규칙이 하나 늘 때 구조가 어떻게 바뀌는지가 이 프로젝트에서 배운 것입니다.
