Redis — 그리고 그 약점을 먼저

if SISMEMBER(students, id) then

  return -2 -- 중복

local n = DECR(remaining)

if n < 0 then INCR; return -1 end

SADD(students, id)

두 명령으로 나누면 그 사이가 다시 열립니다. Redis 는 스크립트 하나를 통째로 원자적으로 실행합니다.

중복 검사가 특히 쌉니다 — 같은 조건에서 M1 의 40배. 예외를 던지고 트랜잭션을 되감는 비용이 없습니다.

좌석이 증발한다

Redis 선점은 성공했는데 DB INSERT 가 실패하면 되돌려야 합니다. 되돌리기 직전에 프로세스가 죽으면 그 자리는 아무도 앉지 못한 채 남습니다. 멱등 키 · outbox · 재조정 배치 — 셋 다 넣지 않았습니다.

약점을 먼저 말하는 것이 가장 강한 카드입니다. 보상 로직이 동작하는 것은 실증했지만(FK 위반으로 INSERT 를 실패시켜 좌석이 유지되는 것을 확인), 보상 자체가 실패하는 경우는 막지 못합니다.
